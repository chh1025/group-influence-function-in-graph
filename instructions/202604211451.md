# Experiment Plan: Clusterwise Influence via Graph Partitioning

## 1. Goal

We want to evaluate a simple **cluster-then-sum** approximation for group influence.

Given a candidate edge-edit set, we will:

1. construct a graph over the candidates or the relevant graph region,
2. partition it into clusters using predefined partitioning methods,
3. compute influence for each cluster independently,
4. sum the cluster influences.

We compare this against:
- **Baseline 1**: whole-group one-shot influence computation
- **Baseline 2**: PBRF / original whole-group influence computation

The main question is:

> Can partitioning the candidate set into clusters and summing clusterwise influences approximate the full group influence better than one-shot group influence, especially for larger candidate sets?

---

## 2. Fixed Clustering Methods

Use exactly the following clustering / partitioning methods:

1. **METIS k-way partition**
2. **Spectral clustering (normalized cut)**
3. **Local PPR-based partition**

Do not add other clustering methods in this experiment unless explicitly needed for debugging.

---

## 3. Overall Experimental Protocol

For each dataset / model / candidate set:

1. Prepare a candidate edit set `S`.
2. Build a partitioning graph or partitioning input suitable for the chosen clustering method.
3. Partition `S` into `K` clusters using one of:
   - METIS k-way partition
   - spectral clustering
   - local PPR-based partition
4. For each cluster `C_k`, compute its influence independently:
   \[
   I(C_k)
   \]
5. Compute summed clusterwise influence:
   \[
   \hat I_{\text{cluster-sum}}(S) = \sum_k I(C_k)
   \]
6. Compare this against:
   - one-shot whole-group influence `I(S)`
   - PBRF / original whole-group influence
   - actual influence from retraining or fine-tuning if available

Repeat for multiple candidate-set sizes and multiple values of `K`.

---

## 6. Partitioning Input Construction

This is a key part of the experiment.

We need a graph or affinity structure over candidates so that the three partitioning methods can be applied consistently.

Please implement a reusable candidate-level graph construction module.

### 6.1 Candidate Graph Nodes
Each node in the candidate graph corresponds to one candidate edge edit.

### 6.2 Candidate Graph Edges / Affinities
Construct candidate-candidate affinity using graph-structural interaction.

Use at least one clear default definition.

### Default recommendation
Define candidate-candidate affinity based on **structural proximity or overlap in the original graph**.

Examples:
- shared endpoint indicator
- shortest-path distance between candidate edges
- overlap of local neighborhoods around the two candidate edges
- overlap of affected node sets if already cheaply available

Please implement one robust default affinity and make it modular so other affinity definitions can be swapped later.

### Important
The same candidate graph / affinity should be used consistently across:
- METIS partition
- spectral clustering
- local PPR partition

as much as possible, so the comparison is fair.

## 7.3 Local PPR-based partition
Use a local partitioning method based on personalized PageRank.

Goal:
- generate locally coherent clusters around seeds

Requirements:
- define seed selection strategy clearly

- log cluster size distribution

If there are multiple reasonable implementations, choose a simple and reproducible one.

## 8. Clusterwise Influence Computation

After partitioning, for each cluster `C_k`:

1. collect the candidate edits in that cluster
2. compute influence for the cluster as a group using the existing influence code
3. sum over clusters

That is:
\[
\hat I_{\text{cluster-sum}}(S) = \sum_{k=1}^K I(C_k)
\]

This summed estimate is the main output of the method.

---
